It keeps notes in Markdown. It asks before it edits.

± No benchmark and no savings figure anywhere on this page.

Nova is a coding agent for the terminal, and it leaves its work where you can find it. Memory is a wiki of Markdown pages you can read, search and delete. Plans wait for your approval. Sessions run side by side, and the model is yours to pick, hosted or local.

What it knows

Notes it can read back, and a council that argues before anything gets written. Both live in files you can open.

01.1 · memory wiki

Memory you can explore.

Nova stores preferences and topic notes in readable Markdown. A compact home index routes to topic maps and related pages, and lessons about one repository stay scoped to it.

± A fresh install starts with the memory scaffold. The wiki develops around notes that exist, not before.

What /dream does

It prepares backups and navigation, then asks the agent to consolidate the notes. Maintenance checks local links and keeps each topic body intact.

What it does not do

Navigation maintenance does not establish whether a remembered claim is true. That is the reader's job, and the page keeps the dates visible for it.

01.3 · /council

A council before the code changes.

Three proposals, written independently. They critique each other anonymously, rank the survivors, and a judge writes the reasoning. You pick one. Selection is not approval: handing the plan to implementation is a separate step.

plan a

4 OF 6 VOTES

Extract a worker process behind a queue

Move ingestion into its own process, talk over a queue, and keep the CLI as a thin client.

critique: two deployment units to run and a queue to supervise. The split earns its keep only above one worker.

plan b

2 OF 6 VOTES

Split the package, share the core

Keep one process, cut the module along its seam, and share the core package.

critique: the seam that looked clean in the tree is a shared connection pool at runtime.

plan c

0 OF 6 VOTES

Ship the interface first

Define the boundary, migrate callers, and leave the implementation where it is.

critique: nothing becomes parallel, so the original motivation is untouched.

plan a selected · review the diff against the current CLI, then approve implementation separately

Council participants have no bound tools, so they cannot edit the repository. Diverse personas are not necessarily different models, and a vote does not prove the winning plan is correct. It uses several model calls.

Read the command docs
01.4 · /council web

Then let the advisors argue it out.

A three-stage discussion in the browser workspace: advisors analyse a decision brief in parallel, vote on the actual options with reasons, and a chairman streams a synthesis that reconciles the disagreements and keeps the minority concern on the page.

synthesized consensus

CHAIRMAN · OPTION 2 · 2 OF 3 BALLOTS

Move sign-in to the provider's OAuth flow and keep API keys for headless runs.

Two advisors weighed user friction above setup cost. The security advisor voted for option 1 and its concern stays in the record: a second credential path is a second thing to revoke.

next step: list where API keys are read today, before anything is written.

  • product advisor

    Does a person sign in once per machine, or once per session? That decides how much friction OAuth removes.

    ballot: option 2 · fewer prompts at first run

  • architecture advisor

    Option 2 fits the existing credential store. Headless runs still need keys, so both paths stay.

    ballot: option 2 · reuses the store

  • security advisor

    Two credential paths double what has to be revoked when a laptop goes missing.

    ballot: option 1 · one path to audit

± Presets apply without overwriting your saved model assignments. Votes are advisory, and the chairman reads visible analyses rather than hidden reasoning. Consensus does not make an answer correct.

What it does

Specialists, scripts, parallel tabs and a workspace beside the terminal. The boundary of each one is printed with it.

02.1Specialist agents 02.2Code Mode 02.3Sessions and tabs 02.4Cowork
02.1 · agents

Specialists take the side work.

Delegate exploration, bug fixes, refactors, reviews, security and dependency checks, tests, documentation or browser automation. Results you need now come back in the same turn; independent jobs run in the background while you keep typing.

agents

@code-explorer where is SessionState built?

  • completedcode-explorer3 call sites found
  • runningtest-runnertests/agents
  • faileddependency-auditserver unreachable

three statuses, one line each

Write your own, by file

Agent definitions are files with a project or global scope, and a project definition overrides a global one with the same name. Each specialist can carry its own selection of skills instead of the whole library. /agents lists them, and edits apply at the next turn without clearing the conversation.

  • @nameresolves a known agent
  • retriesbounded, per model call
  • statusplain inline lines

± Background agents need the optional agents-server install; /agent-server reports what is missing. Persistent teams are experimental and off by default, under /settings → Experimental.

02.2 · code mode

Ten tool calls, one script.

Turn on Code Mode under the composer and the agent can combine eligible native and MCP tools in a short JavaScript function: loops, branches, dependent calls and bounded parallel work. Intermediate results stay in the script. Only what it returns reaches the model.

code mode · one script, two folders
// discover a tool, then call it across two folders at once const found = await tools.list(); const spec = await tools.describe(found[0].name); const dirs = ["src", "tests"]; const runs = await Promise.all(dirs.map(d => tools.call(spec.name, { path: d }))); return runs.map((r, i) => ({ dir: dirs[i], size: r.length })); // only this is returned

The same rules apply inside

Nested calls go through the configured tool inventory, argument validation, middleware and approval decisions, exactly as direct calls do. Memory, code size, run time, call count and concurrency are all bounded, and interrupting the script cancels pending work.

Where it stops

The script has no host imports, filesystem or network of its own. Delegation, questions to you, workspace changes and calls that need interactive approval stay direct. External side effects cannot be rolled back.

± Native workflows need no MCP server; mcp.list, mcp.describe and mcp.call need configured servers. The script above is illustrative; arguments follow each tool's own schema.

02.3 · sessions and tabs

Project agents that can talk to each other.

Run parallel session tabs and address another live tab with @tab:<session-id> <message>. Requests queue while the recipient is busy, and linked replies appear in both transcripts, with controls to open the other tab or attach the reply to your draft.

frontend · you

@tab:api-3f2 is GET /v2/ingest still returning 200 after the queue change?

↳ api-3f2 replied 11:04 · 2 files read

waiting on api-3f2 … open tab attach to draft
api · you

Extract the ingest worker, keep the routes where they are.

nova · editing ingest/worker.py …

• 1 message queued while this tab is busy

↩ sent to frontend 11:04

Agents can message too

The SendMessage tool lets the agent write to another live tab by session ID or tab title, find recipients with list_sessions, and keep each reply linked to the request that asked for it. /tabs launches, switches and closes project sessions, each with its own model, draft and scroll position.

Feature work in its own worktree

Ask Nova to enter a worktree and it creates a fresh branch from HEAD, then moves its file and shell tools there. Leaving keeps the branch, commits and uncommitted changes for review, and your original checkout is never touched. Needs Git and at least one commit.

± Messaging connects tabs within one Nova window. Each recipient keeps its project and approval boundaries, only the explicit message is shared, and pending messages are held in memory.

03.1 · /model

The model is a setting, not a commitment.

Nova speaks to hosted providers and to local Ollama models. /model sets the main agent and the delegated roles. Optional /router profiles pick among configured routes per turn using a decision model, and fall back to the default route when that decision fails.

Among the 18 providers /auth can configure: Azure OpenAI, Amazon Bedrock, Mistral, Groq, Cerebras, xAI, Hugging Face, Command Code, OpenCode Go and Zen, Kimi For Coding and MiniMax, plus ChatGPT and Google sign-in. /effort sets reasoning effort where the model supports it.

± Routing is off by default and needs configuration. Model capabilities, credentials and provider charges still apply, and while local inference is available, selecting it does not make every external integration offline.

03.2 · /remote

Follow the session from your phone.

Each Nova session gets its own Telegram topic or Discord thread. Prompts, tool activity and streamed replies arrive there as they happen, and an authorized sender can answer from the chat.

telegram

one topic per session

Prompts, photos and captioned images; task checkboxes, stacked tables and expandable diffs laid out for a phone; numbered controls for interactive panels.

discord

one thread per session

Thread or forum post per session, restored on reconnect and archived when the session closes; missing channel permissions are reported plainly.

rootapp

optional companion

An authorized community channel through Root's local DevHost integration, with its own build, Bot ID and sender setup.

± Each service needs its own account, bot, channel permissions and authorized senders, managed through /remote. A bridge never widens Nova's workspace permissions. Several Nova windows share one Telegram polling connection instead of competing for updates.

03.3 · /caveman

Say less. Read less. Keep the exact text.

Caveman mode is six independent switches for verbosity and context, behind one opt-in master switch on the composer. Compacted output stays recoverable, so the agent can always go back to the exact source.

say less
Terser prose. Code and identifiers stay exact; warnings and ambiguity keep full sentences. Six intensities from lite to wenyan-ultra.
read less
Logs, JSON and CSV are shortened in the model's view while the exact source stays recoverable.
browse
HTML and Markdown results are compacted with references kept for exact recovery.
blocks
Find an exact script from an earlier tool call and rerun it through the normal tool, under current permissions.
auto routing
Use your router choices and per-route effort without changing the saved session model.
waste fixes
Fewer duplicate tool results, with local estimates shown beside provider-reported usage and cache figures.

No savings figure is promised.

Results vary by model and task, and a shorter answer can still use more total tokens on a reasoning model. /caveman audit compares the local estimates with what the provider reported. Your reply language is preserved at every intensity.

03.4 · /share artifacts

Results you can open outside the terminal.

Ask for an HTML page, a Markdown report or a dashboard and Nova makes it an artifact. Updating it keeps the same ID and records a new version. The session's collection is searchable by title, type or ID.

artifacts · this session
  • ingest-report.htmlv3
  • queue-latency.mdv1
  • council-notes.htmllive

/share list · https://<random>.trycloudflare.com

A link for the people you choose

When cloudflared is installed, Nova opens a temporary Cloudflare Quick Tunnel for the collection. Resuming a saved session restores the artifacts, and a fresh tunnel can share them again. /share list shows what is live and /share stop ends it.

What the link is not

Anyone with the URL can open it, it changes on restart, and it ends when Nova or the viewer stops. It is not hosting, authentication or an uptime promise. Without cloudflared the artifacts still work locally.

Each interface style brings its own home screen and carries through conversation, tool and dialog views, independently of the colour theme. Home screens offer Explain, Refactor, Build and Debug starters that fill an editable prompt.

Talk to it, hear it back

Dictate a request and hear a short spoken summary of the final reply, never the tool output or reasoning. Faster-Whisper and Piper are the defaults; Whistle and Parakeet add speech input, and Kokoro and sanoTTS are light CPU voices. Piper starts speaking sentence by sentence.

What it needs

The voice extra plus the extra for any provider you pick, a working microphone and speakers, and the model downloads. /voice download fetches them ahead of time with real progress rows above the composer. Latency and accuracy are not benchmarked.

± Animated homes are optional: low-resource mode pauses them, and short terminals give the space to the composer. The status line is customisable with a live preview in /statusline.

03.6 · /computer

Its own computer. Preview.

A session-owned Linux VM on your machine, run by QEMU with 2 CPUs and 4 GiB of RAM, with no cloud account. A private browser view shows what Nova sees. It clicks, types and scrolls only against its latest screenshot, under the same approvals as any other tool.

what stays separate
guest · owned by one session ├── host project files not mounted ├── clipboard, browser profiles not copied ├── credentials not copied └── delegated agents get no desktop tools you · pause, resume, stop └── pause holds even with auto-approve on

A preview, not a promise.

Offline lifecycle, approval and preview tests pass, but a real guest boot has not been verified yet, so treat this as a preview. Needs the computer extra, QEMU, disk space for the first image and a vision-capable model. The guest can reach the network.

The record

Where the decisions end up once you walk away: plans on disk, approvals per operation, and a recovery path that is not a promise.

04.1Plans 04.2Approvals and recovery 04.3Everything else 04.4Install 04.5Questions
04.1 · plans

Plans you can find again.

Read-only planning separates investigation from implementation. Approved plans live next to their project, and a copy is mirrored to a global archive so a later session can find the reasoning, not just the summary.

user-approved plans · project and archive
your-repo/ ├── .nova/plans/ │ ├── plan-extract-ingest-worker.md approved │ └── plan-lazy-memory-index.md approved └── ~/.nova/plans/ ├── your-repo/ │ ├── plan-extract-ingest-worker.md mirror │ └── plan-lazy-memory-index.md mirror └── other-project/ └── plan-tidy-colour-tokens.md auto, archive only

Approve once, read it back in any later session

The agent's recent_plans tool lists both locations for the current project and reads the saved Markdown, so a committed decision comes back with its reasoning attached.

  • <project>/.nova/plans/project plans
  • ~/.nova/plans/<slug>/mirrored
  • auto-approvedarchive only

± Plans approved automatically stay only in the global archive, so it never looks like you signed off on something you did not see. Optional /claude-plan and /codex-plan bring their own installation and account requirements.

04.2 · trust

Nothing here changes behind your back.

Three things decide how far Nova can go on its own: what it learned, what still needs your approval, and what you can get back afterwards. Each one is a file you can read.

learning · with a ledger
nova > cat ~/.nova/refinement_events.json { "kind": "skill", "name": "verify-pytest-before-commit", "scope": "project", "evidence": "3 of 4 sessions here committed before running the suite", "status": "awaiting your decision" } [a]pprove and activate [r]evise [d]iscard nothing is written until you choose

Learning, with a ledger

When a run finishes, Hermes can review it and prepare a lesson, a habit, a skill or a prompt proposal. Each item lands in a versioned local ledger with its scope, the evidence it came from and its status.

± Approval and activation are separate steps, and a generated proposal is not treated as your instruction. Reviews add provider usage.

Approval, per operation

Editing a file, running a command, reaching the network: each has its own policy in .nova/approval-policy.json. Nova stops and asks when the policy says ask, and answers with the operation it wants to run.

± Hard-coded denials cannot be loosened by that file. In a headless run --deny-tools rejects approval requests so a pipeline stops instead of waiting; it does not disable every tool, and it is not a read-only sandbox.

Recovery, on your disk

Context archives keep checksummed manifests so a compacted conversation can be inspected later. File snapshots let you browse and restore supported edits, and saved sessions keep their project, model and continuation details.

± Compaction is not perfect recall, and snapshot coverage depends on the operation. Large files can be skipped. Neither replaces version control.

04.4 · install

Three commands and you are running.

Python 3.11 or newer and uv. The recommended install is a uv tool install; once installed, the command is nova. For local development you clone, sync, and run uv run nova.

macOS and Linux · installed copy

uv tool install "novacode-cli @ git+https://github.com/Babitdor/NovaCode.git"

windows · from source

git clone https://github.com/Babitdor/NovaCode.git; cd NovaCode; uv sync

any platform · then run

nova

Voice is optional and pulls its own model downloads. uv sync --extra voice adds local speech in and out; voice-whistle, voice-orpheus (about 2 GB), voice-parakeet, voice-pocket and the Kokoro and sanoTTS voices are separate opted-in extras, and the microphone and speakers are yours. The computer preview and Bedrock are extras too.

± An installed copy is not a development checkout. If you want to change Nova, use the clone path and uv run nova, or your edits will not load.

04.5 · questions

Questions people ask first.

The twelve that come up before installing. Each answer says what it does, then where it stops.

What does Nova remember between sessions?

Preferences and topic notes as readable Markdown, in your own directory. A compact home index routes to topic maps and related pages, and lessons about one repository stay scoped to it. The agent can search that memory and open the full page behind a result. Look at it yourself: ~/.nova/agents/<agent>/memories/INDEX.md.

What does /dream actually do?

It prepares backups and navigation, then asks the agent to consolidate the notes. Maintenance checks the local links and keeps each topic body intact. A fresh install starts with the memory scaffold, and the wiki grows around whatever you have written down. Navigation maintenance does not confirm that a remembered claim is still true.

What is the council for?

Comparing approaches before you commit to one. /council <task> runs independent proposals through critique, anonymous ranked voting and a judging stage, then puts up to three plans in front of you. Use /council web for live discussion between advisors debating actual options with a chairman synthesising disagreements.

Can two sessions in different projects talk?

Yes. Run parallel tabs and address another one with @tab:<session-id> <message>. Requests queue while the recipient is busy, and linked replies appear in both transcripts. Messaging runs inside one Nova window today, each tab keeps its own project and approval boundaries, and only the explicit message is shared.

Which models can I use?

Hosted providers and local Ollama models. /model sets the main agent and the delegated roles, so a cheaper model can handle background work. Optional /router profiles pick a route per turn with a decision model; routing is off by default and falls back to the default route when its decision path fails.

Where do approved plans end up?

A plan you approve is saved in <project>/.nova/plans/ and mirrored to ~/.nova/plans/<project-slug>/. Plans approved automatically stay only in the global archive, so it never looks like you signed off on something you did not see.

Does the self-improvement retrain my model?

No. There is no training anywhere in Nova, and nothing is uploaded to change a model. What changes are files on your disk: a skill written from a repeated failure, a prompt candidate promoted after enough runs, tuned thresholds. You can read all of them, and roll them back.

What happens when a tool call needs approval?

It stops and asks you, configurable per operation in .nova/approval-policy.json. Hard-coded denials, like rm -rf /, cannot be loosened by that file. Headless runs are the exception: --deny-tools rejects approval requests so a pipeline stops rather than waiting. That is not the same as disabling every tool.

Can I use it away from my machine?

Yes, with integration config. Each session gets its own Telegram topic or Discord thread, with prompts, tool activity and replies streamed into it, and an optional Rootapp companion covers a community channel. Only senders you authorize through /remote can prompt it. Scheduled /cron tasks need Nova to be running.

What is Cowork?

A local workspace that opens beside the terminal, with folder access, tasks and activity on one side and the conversation on the other. You can grant or revoke a folder while Nova works. It is not shared publicly, and folder grants are not an operating-system sandbox.

How much does Caveman mode save?

There is no fixed number, and the page will not quote one. Savings depend on the model and the task, and a shorter visible answer can still use more total tokens on a reasoning model. /caveman audit shows local estimates next to the usage your provider actually reported.

Are shared artifact links private?

No. A temporary Cloudflare link opens for anyone who has it, changes when Nova restarts, and stops when Nova or the local viewer stops. Use /share stop to end it early. Sharing a whole session with bare /share is different: after you confirm, it uploads an export as a secret GitHub gist, which is unlisted rather than private.
