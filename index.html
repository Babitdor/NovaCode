Product

  • Name: NovaCode / Nova — open-source terminal coding assistant/agent (MIT). Source.
  • Headline: A coding agent with readable memory. Open source. Runs in your repository.
  • What it does: Give Nova a task in your repository. It explores code, edits files, and runs commands in your terminal. You can review plans before implementation and configure which tool actions need approval.
  • Requirements (as stated): Python 3.11+, MIT licensed, hosted or local models (macOS/Linux/Windows; some providers require credentials).
  • Canonical pages: Home · Documentation · Feature guide · Changelog · llms.txt · sitemap.xml

Install

  • Windows CMD, macOS and Linux: uv tool install --python 3.11 novacode-cli installs the latest release from PyPI.
  • Common extras: uv tool install --python 3.11 --force "novacode-cli[browser,voice,agents-server,server,bedrock,computer]". Keep all wanted extras when reinstalling; external runtimes and voice models may need separate setup.
  • Upgrade: uv tool upgrade novacode-cli. To replace a Git-based installation, use uv tool install --python 3.11 --force novacode-cli.
  • Run: nova. Note: an installed copy is not a development checkout; to work on Nova itself use the source checkout (uv run nova as documented).

Workflow

  1. Describe the change: point Nova at a repository and explain the bug, feature, or question.
  2. Work with the code: Nova explores relevant files, proposes plans when useful, and makes changes using its coding tools.
  3. Inspect the result: review conversation/file changes; ask Nova to run the checks your project needs.

Readable memory

  • Preferences/topic notes are kept in readable Markdown on your machine (example: ~/.nova/agents/<agent>/memories/).
  • Memory is context, not verification. You can read, edit, search, or remove notes.
  • Memory documentation

Plans and approvals

  • Plan mode lets Nova investigate before changing code; review the approach before implementation.
  • Tool approvals follow a configurable policy; hard-coded denials are still enforced.
  • Approved plans are saved with the project and in Nova's archive (as stated on page).
  • Security/permissions documentation

FAQ highlights

  • What does Nova do? Open-source terminal coding agent; explores repos, edits files, runs commands, helps understand code.
  • Where is memory kept? Markdown under ~/.nova/agents/<agent>/memories/; user-readable/editable.
  • Do I approve every action? Configurable by operation; plan mode for review; hard-coded denials cannot be disabled by policy.
  • Models/OS? Hosted providers and local Ollama; Python 3.11+; macOS/Linux/Windows.

Memory you can inspect

Useful notes live in files you can open, search, edit, or remove.

A Markdown wiki, on your machine.

Nova keeps preferences and topic notes in readable Markdown. It can search the notes and open the source page, so you can see what it is using as context.

You stay the source of truth

Memory is ordinary text, not a hidden profile. Read it directly, correct it when a detail changes, or delete notes you no longer want Nova to use.

Find the wiki in ~/.nova/agents/<agent>/memories/.

Memory can provide context; it does not prove that a remembered claim is still true.

Before you install.

The practical details for getting started.

What does Nova do?

Nova is an open-source coding agent for the terminal. It can explore a repository, edit files, run commands, and help you understand the code. Read the documentation.

Where does Nova keep memory?

In Markdown files under ~/.nova/agents/<agent>/memories/. You can read and edit these files yourself. Memory is context, not verification.

Do I approve every action?

Tool approvals are configurable by operation. Plan mode lets you review an approach before implementation, and hard-coded denials cannot be disabled through the approval policy. See permission details.

Which models and operating systems are supported?

Nova supports hosted providers and local Ollama models. It requires Python 3.11 or newer and runs on macOS, Linux, and Windows. Some providers need their own account or API credentials.

Point it at a repository.

Approval still applies. Memory still lands in files you can read. The first thing it does is look around before it touches anything.
