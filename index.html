Agent view — NovaCode landing (linear)

This is the full landing page transformed for AI agent readability. Toggle to Human for the visual presentation. Verify current behavior, versions, and limits against the docs, changelog, and source repository.

Product

  • Name: NovaCode / Nova — open-source terminal coding assistant/agent (MIT). Source.
  • Headline: A coding agent with readable memory. Open source. Runs in your repository.
  • What it does: Give Nova a task in your repository. It investigates, plans, edits files and runs your checks. Beyond that it delegates to specialist agents, runs Claude Code and Codex alongside itself in project rooms, compares options in a Council, and reports verification evidence instead of a completion claim.
  • Requirements (as stated): Python 3.11+, MIT licensed, hosted or local models (macOS/Linux/Windows; some providers require credentials).
  • Canonical pages: Home · Documentation · Feature guide · Changelog · llms.txt · sitemap.xml

Install

  • Windows CMD, macOS and Linux: uv tool install --python 3.11 novacode-cli installs the latest release from PyPI.
  • Common extras: uv tool install --python 3.11 --force "novacode-cli[browser,voice,agents-server,server,bedrock,computer]". Keep all wanted extras when reinstalling; external runtimes and voice models may need separate setup.
  • Upgrade: uv tool upgrade novacode-cli. To replace a Git-based installation, use uv tool install --python 3.11 --force novacode-cli.
  • Run: nova. Note: an installed copy is not a development checkout; to work on Nova itself use the source checkout (uv run nova as documented).

What is different here

  • Delegation: specialist agents in-process and in the background, /rooms project channels with agent DMs and a shared task board, an embedded Claude Code or Codex conversation per channel, and /council / /council web for proposals, ballots and a chairman's synthesis.
  • Memory: a linked Markdown wiki with visible recall notices, /dream consolidation and backups, plus a source-validated workspace knowledge cache (/cache).
  • Verification: /prime Deep Work tracks define, investigate, implement, verify, challenge and deliver, and evaluates acceptance checks against real tool-call output.
  • Context: model-controlled compression folds completed ranges into summaries while exact originals stay searchable (compress, decompress, search_context, acp_status).
  • Tooling: /onboard builds a local code graph with tours and change impact; Code Mode (eval) runs bounded JavaScript over eligible tools; /cc Command Center lists sessions by project and status; /loop schedules recurring work.
  • Interfaces: 14 interface styles, Lite Mode (Off / Caveman / Ponytail), artifacts with temporary Cloudflare previews, Telegram/Discord/Rootapp bridges, voice in and out, and a VISION side-call for text-only models.
  • Preview and experimental: the local QEMU Linux desktop is a preview; agent teams and swarm scheduling are experimental and off by default.

Readable memory

  • Preferences, topic notes and habits are kept in readable Markdown on your machine (example: ~/.nova/agents/<agent>/memories/).
  • Automatic recall is visible: the transcript says when memory was recalled or a page was read, and names the source path.
  • Memory is context, not verification. You can read, edit, search, or remove notes.
  • Memory documentation

Plans and approvals

  • Plan mode keeps investigation read-only and blocks edits, memory writes, command execution and MCP or Code Mode calls; auto-approval cannot override it.
  • Tool approvals follow a configurable policy; hard-coded denials are still enforced, and uncertain auto-approval reviews fail closed.
  • Approved plans are saved with the project and in Nova's archive (as stated on page).
  • Security/permissions documentation

FAQ highlights

  • What does Nova do? Open-source terminal coding agent; investigates the repository, plans, edits files, runs commands, and verifies the result.
  • Where is memory kept? Markdown under ~/.nova/agents/<agent>/memories/; user-readable/editable.
  • Do I approve every action? Configurable by operation; plan mode for review; hard-coded denials cannot be disabled by policy.
  • Can other agents join? Yes — specialists, an embedded Claude Code or Codex channel in /rooms, and Council advisors.
  • Models/OS? 18 hosted provider IDs and local Ollama; Python 3.11+; macOS/Linux/Windows.

01

Several agents, one terminal

Specialists, an embedded Claude Code or Codex channel, and a Council that argues before it recommends.

Work is delegated, not flattened.

Independent work goes to specialists, background runs keep their own lane, and a project gets channels instead of one growing conversation.

Specialist agents

Fourteen definitions cover exploration, bugs, refactors, review, security, dependencies, performance, docs, tests and browser work. In-process calls answer inside your task; background agents keep running while you read.

Project rooms

/rooms opens project channels, agent DMs and one shared task board. Nova can also run Claude Code or Codex from their installed CLIs in a channel: separate resumable conversations, attributed replies, approved handoffs.

Council

/council web sends a decision brief to advisors who ask questions, vote on real options and disagree in public. A chairman reconciles the result and keeps minority concerns. Votes are advisory; you approve the outcome.

± Background agents need the agents-server extra. Rooms limit a project to two workers and six initial task turns; extensions need a separate owner decision. Teams and swarm scheduling stay experimental and off by default.

02

Memory you can inspect

Useful notes live in files you can open, search, edit, or remove.

A Markdown wiki, on your machine.

Preferences, topic notes and habits live in readable Markdown: an index, topic maps, project-scoped pages. Recall is visible — when notes enter a turn, the transcript names the source file.

You stay the source of truth

Memory is ordinary text, not a hidden profile. Read it directly, correct a detail that changed, delete notes you no longer want Nova to use.

/dream consolidates the wiki with backups and reports broken links. /cache status shows the source-validated workspace cache behind repeated questions about this project.

Find the wiki in ~/.nova/agents/<agent>/memories/.

± Memory provides context; it does not prove a remembered claim is still true.

03

Proof, not a completion claim

Nova records what it ran, what it saw, and what it could not check.

It reports what it observed.

Deep Work (/prime) keeps a task inside six checkpoints and separates the agent's own assessment from evidence produced by your tools.

Checks before claims

Acceptance checks are written before normal tool work and bound to the real tool-call IDs of that run. Exit codes and literal output are evaluated mechanically, so a fabricated, missing or truncated result cannot pass.

Six checkpoints

  1. 01Define
  2. 02Investigate
  3. 03Implement
  4. 04Verify
  5. 05Challenge
  6. 06Deliver

Interrupted work stays paused, late results cannot repopulate a cleared request, and an unmet criterion is reported even when every phase finished.

Kept with the session

The report, task history and check evidence persist with the session. /prime tasks, /prime checks and /prime resume <id> reopen them; project-scoped findings are shared across linked worktrees.

± Deep Work is opt-in: /prime on or --prime. Verification is only as good as the checks you define; an unverified result is labelled, not hidden.

04

You set the boundaries

Read-only planning, approvals that fail closed, and isolation when you need it.

Review plans. Set tool approvals.

Plan mode keeps investigation read-only, approvals fail closed rather than open, and a risky change moves into its own Git worktree before anyone touches the original checkout.

Plan mode is enforced

Planning blocks edits, memory writes, command execution and calls routed through MCP or Code Mode — including when auto-approval is on. Executing a plan still needs your approval, and approved plans are saved with the project and in Nova's archive.

Approvals that fail closed

Tool policy, scoped path grants and explicit denies. A decision model can review routine calls, but uncertain or unavailable verdicts come back to you, and traversal, drive, UNC and device escapes are rejected.

Isolation when it matters

EnterWorktreeTool moves the session into a fresh Git worktree and back without losing work; /worktree pairs one with a session. Code Mode runs bounded JavaScript over eligible tools, and its nested calls keep the same approval path.

Before you install.

The practical details for getting started.

What does Nova do?

Nova is an open-source coding agent for the terminal. Beyond reading a repository, planning, editing files and running your checks, it delegates work to specialists, keeps project channels alongside Claude Code and Codex, and reports verification evidence instead of a completion claim. Read the documentation.

Where does Nova keep memory?

In Markdown files under ~/.nova/agents/<agent>/memories/. You can read and edit these files yourself. Memory is context, not verification.

Do I approve every action?

Tool approvals are configurable by operation. Plan mode lets you review an approach before implementation, and hard-coded denials cannot be disabled through the approval policy. See permission details.

Which models and operating systems are supported?

18 hosted provider IDs plus local Ollama models, with independent roles for the main agent, subagents, async agents and a vision companion. Nova requires Python 3.11 or newer and runs on macOS, Linux, and Windows. Some providers need their own account or API credentials.

Can other agents work alongside Nova?

Yes. Specialist agents cover exploration, fixes, review, security, tests and more; /rooms adds project channels where Nova can also run Claude Code or Codex from their installed CLIs, and /council web gathers advisor proposals and ballots. Background agents need the agents-server extra, and agent teams stay experimental.

How does Nova show its work?

Deep Work (/prime) defines acceptance checks before implementation and evaluates them against real tool-call output, then reports unmet criteria and unverified work rather than a completion claim. See verification details.

Point it at a repository.

Approval still applies. Memory still lands in files you can read. Delegated work keeps its own channel, and the first thing Nova does is look around before touching anything.
