    What /dream does

    It prepares backups and navigation, then asks the agent to consolidate the notes. Maintenance checks local links and preserves topic bodies.

    What it does not do

    Navigation maintenance does not establish whether a remembered claim is true. A new install starts with its memory scaffold; the wiki develops around accumulated notes.

    ❯/council split the ingest worker out of the CLI

    A council before the code changes.

    Three proposals, written independently. They critique each other anonymously, rank the survivors, and a judge writes the reasoning. You pick one. Selection is not approval: handing the plan to implementation is a separate step.

    Plan A selected · review the diff against the current CLI, then approve implementation separately.

    Council participants have no bound tools, so they cannot edit the repository. Diverse personas are not necessarily different models, and a vote does not prove the winning plan is correct. It uses several model calls.

    ❯/council which auth flow is least invasive?

    A council that debates before it concludes.

    Open /council web for live discussion between multiple advisors. They ask each other clarification questions, vote on actual options, and a chairman reconciles disagreements into a reasoned synthesis — while keeping minority views visible.

    Clarify

    Advisor A: Does OAuth or API-key matter for user friction vs. security posture?

    Debate

    Advisor B: Both work, but the question scope changes with the threat model.

    Synthesise

    Chairman: Option 2 has stronger user trust but requires provider sign-in setup.

    Votes are advisory only — you still choose what to implement.

    Presets like Code Audit, Architecture and Creative Debate apply without overwriting saved assignments. This is separate from the planning /council workflow.

    Nothing here changes behind your back.

    Three things decide how far Nova can go on its own: what it learned, what still needs your approval, and what you can get back afterwards. Each one is a file you can read.

    Learning, with a ledger

    When a run finishes, Hermes can review it and prepare a lesson, a habit, a skill or a prompt proposal. Each item lands in a versioned local ledger with its scope, the evidence it came from and its status.

    Where it stops: approval and activation are separate steps, and a generated proposal is not treated as your instruction. Reviews and other auxiliary model work can add provider usage.

    Approval, per operation

    Editing a file, running a command, reaching the network: each has its own policy in .nova/approval-policy.json. Nova stops and asks when the policy says ask, and answers with the operation it wants to run.

    Where it stops: hard-coded denials cannot be loosened by that file. In a headless run, --deny-tools rejects approval requests, so a pipeline stops instead of waiting on a prompt nobody is there to answer. It does not disable every tool, and it is not a read-only sandbox.

    Recovery, on your disk

    Context archives keep checksummed manifests so a compacted conversation can be inspected later. File snapshots let you browse and restore supported edits, and saved sessions keep their project, model and continuation details.

    Where it stops: compaction is not perfect recall, and snapshot coverage depends on the operation. Large files can be skipped. Neither replaces version control.

    Three commands and you are running.

    Python 3.11 or newer and uv. The recommended install is a uv tool install — once installed, the command is nova. For local development you git clone, sync, and use uv run nova.

    git clone https://github.com/Babitdor/NovaCode.git
    cd NovaCode && uv sync
    uv run nova

    For an installed copy (not development), install as a uv tool — the command is nova.

    git clone https://github.com/Babitdor/NovaCode.git
    cd NovaCode; uv sync
    uv run nova

    For an installed copy (not development), install as a uv tool — the command is nova.

    uv tool install "novacode-cli @ git+https://github.com/Babitdor/NovaCode.git"
    nova

    Voice is optional and pulls its own model downloads. uv sync --extra voice adds local speech in and out; voice-orpheus (about 2 GB), voice-parakeet and voice-pocket are separate opted-in extras, and the microphone and speakers are yours.

    Questions people ask first.

    What does Nova remember between sessions?

    Preferences and topic notes as readable Markdown, in your own directory. A compact home index routes to topic maps and related pages, and lessons about one repository stay scoped to it. The agent can search that memory and open the full page behind a result. Look at it yourself: ~/.nova/agents/<agent>/memories/INDEX.md.

    What does /dream actually do?

    It prepares backups and navigation, then asks the agent to consolidate the notes. Maintenance checks the local links and keeps each topic body intact. A fresh install starts with the memory scaffold, and the wiki grows around whatever you have written down. Navigation maintenance does not confirm that a remembered claim is still true.

    What is the council for?

    Comparing approaches before you commit to one. /council <task> runs independent proposals through critique, anonymous ranked voting and a judging stage, then puts up to three plans in front of you. Use /council web for live discussion between advisors debating actual options with a chairman synthesising disagreements.

    Can two sessions in different projects talk?

    Yes. Run parallel tabs and address another one with @tab:<session-id> <message>. Requests queue while the recipient is busy, and linked replies appear in both transcripts, with controls to open the other tab or attach the reply to your draft. Messaging runs inside one Nova window today, each tab keeps its own project and approval boundaries, and only the explicit message is shared.

    Which models can I use?

    Hosted providers and local Ollama models. /model sets the main agent and the delegated roles, so a cheaper model can handle background work. Optional /router profiles pick a route per turn with a decision model; routing is off by default and falls back to the default route when its decision path fails.

    Where do approved plans end up?

    A plan you approve is saved in <project>/.nova/plans/ and mirrored to ~/.nova/plans/<project-slug>/. Plans approved automatically stay only in the global archive, so it never looks like you signed off on something you did not see. Later, ask Nova to find the recent plan and it searches both places.

    Does the self-improvement retrain my model?

    No. There is no training anywhere in Nova, and nothing is uploaded to change a model. What changes are files on your disk: a skill written from a repeated failure, a prompt candidate promoted after enough runs, tuned thresholds. You can read all of them, and roll them back.

    What happens when a tool call needs approval?

    It stops and asks you, configurable per operation in .nova/approval-policy.json. Hard-coded denials, like rm -rf /, cannot be loosened by that file. Headless runs are the exception: --deny-tools rejects approval requests so a pipeline stops rather than waiting on a prompt nobody is there to answer — that is not the same as disabling every tool.

    Can I use it away from my machine?

    Yes, with integration config. Bridge it to Discord or Telegram: Telegram takes voice notes, gives each session its own forum topic, and deletes a question once you have answered it. Cron tasks and signed webhooks let other systems start a run. Scheduling depends on the Nova process or service being up.

    What is Cowork?

    A visual workspace that opens beside your work — folder permissions, active tasks, and an activity feed updated in real time while agents write code. Cowork keeps its own permission model per workspace and is a local app with no public endpoint. It works alongside specialist delegates, skills and MCP tools.
