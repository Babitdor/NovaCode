01

A task is finished when the tests pass.

The proof on the front page is a real change to this repository. At 67e94c3^ the compaction test failed. At 67e94c3 it passed. The diff between the two commits is the one shown on the front page, unedited. 

uv run pytest tests/test_context_compaction.py -q
67e94c3^   2 failed, 34 passed
67e94c3    36 passed in 11.68s

What it does not prove. That the change is the best one. It proves the failure is fixed and the rest of the suite still passes.

02

It reads the repository before it answers.

A session starts with a search, not a guess. The plate on the front page is an unedited session: the question, the git log, and an answer that cites it.

Where to check. novacode_cli/core/agent_loop.py is the one event stream every surface renders.

What it does not prove. That it reads the right files every time. That is what the plan step is for.

03

One turn is six steps, and each one is visible.

Read, plan, edit, run, read the failure, retry. The loop is a single async generator, so the terminal, the headless runner and the remote bridges all show the same six steps.

Where to check. tests/test_verification_loop.py.

What it does not prove. That every step runs on every task. A step is skipped when the task does not need it, and the loop reports what it did, not what it should have done.

04

You set the approval policy per operation.

Reads, writes, shell commands and network calls are separate switches. The default is to ask before a write. The policy is a file you can read and change.

Where to check. tests/test_approval_policy.py.

What it does not prove. That every tool is gated. A tool that is not in the policy is not gated.

05

It runs where you already work.

The TUI, -p headless mode, the parallel session worker and the Discord and Telegram bridges all drive the same agent loop.

Where to check. tests/test_headless.py and tests/test_remote_sessions.py.

What it does not prove. That the bridges work without credentials. They need their own, and they are not part of the default install.

06

It improves its prompts, not its weights.

Grading a turn costs one extra model call and is off by default. What changes is on disk: prompts, skills, thresholds. A candidate replaces the current prompt only after enough runs, and it can be rolled back.

Where to check. tests/test_hermes/test_prompt_evolution.py and tests/test_hermes/test_verifier.py.

What it does not prove. That the model got smarter. It did not. The instructions got better.

07

One command installs it.

uv sync resolves the environment and the lockfile. Nothing is installed globally. 

git clone https://github.com/Babitdor/NovaCode
cd NovaCode && uv sync

What it does not prove. That it runs without Python 3.11+ and uv. It does not install a model; you bring your own key.

08

The limits are documented.

The questions section on the front page is the same list that ships in the README. If a limit is not written down, it is a bug.

Where to check. README.md, and the questions section of the front page.

What it does not prove. That the list is complete. Documentation is not a guarantee. The tests are.

09

MIT licensed, runs locally, bring your own model.

The licence is MIT. The agent runs on your machine and talks to the model provider you configure. There is no NovaCode account and no hosted service.

Where to check. LICENSE and novacode_cli/config/model_create.py.

What it does not prove. That your prompts and code stay on your machine. They go to your model provider, under that provider's policy.
