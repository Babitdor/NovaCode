# Nova TUI wire protocol (v1)

The ratatui client (`rust/nova-tui`) is a _frontend_; the Python process is the
_server_ that owns sessions, the agent graph and every side effect. This document
is the contract between them. `novacode_cli/sessions/protocol.py` remains the
single encoder for `ui_events`; `novacode_cli/server/frames.py` only adds the
envelopes needed to carry UI commands over a socket.

Status: **increment 2** (core chat + the command catalogue and the screen
round trip). Anything not listed here is not implemented; `novacode_cli/server/catalog.py`
records which slash commands the server serves today.

## 1. Framing

- Transport: TCP on `127.0.0.1` (loopback only, never a public interface).
- Encoding: UTF-8, **one JSON object per line**, `\n`-terminated. No length
  prefix, no batching, no compression.
- Maximum line length: **8 MiB** (`server/frames.MAX_LINE`), mirroring
  `sessions/supervisor._STREAM_LIMIT` because one `ToolResult` can be large.
  A longer line is a protocol error and closes the connection.
- A line that is not JSON, or is JSON but not an object, is **skipped** — never
  fatal. This matches `protocol.loads`, which returns `None` for noise.
- An unknown `"t"` value (server → client or client → server) is **skipped**.
  An unknown `"c"` inside an `ev` frame is **skipped** (`decode_event` returns
  `None`). Version skew in either direction is therefore survivable: a newer
  build may send frames an older build ignores, and vice versa.
- Strings inside `ui_events` are clipped by `protocol.jsonable` at 256 000
  characters with the marker `… [truncated]` (`protocol.MAX_FIELD`).

## 2. Handshake

```
client                                            server
  | {"t":"hello","protocol":1,"client":"nova-tui/0.1"}  |
  |----------------------------------------------------->|
  | {"t":"hello","protocol":1,"server":"novacode-cli/1.2.54"}
  |<-----------------------------------------------------|
  | {"t":"auth","token":"<32-byte hex>"}                 |
  |----------------------------------------------------->|
  | {"t":"ready","protocol":1,"session_id":"...","cwd":"...","model":"...", ...}
  |<-----------------------------------------------------|
```

- `hello` is sent in both directions so each side learns the other's protocol
  version before any state is exchanged.
- The token is generated by the launcher (`novacode_cli/ui/launcher.py`) with
  `secrets.token_hex(16)` and compared with `secrets.compare_digest`. A wrong
  token gets `{"t":"error","message":"authentication failed"}` and the
  connection is closed. Nothing else is accepted before `ready`.
- A client that sends any frame other than `hello`/`auth` before `ready` is
  closed with an `error` frame.
- `hello` and `ready` both carry `"protocol": 1` (`frames.PROTOCOL_VERSION`).
  A future incompatible change increments it; additive frames do not.

## 3. Envelopes

### 3.1 Client → server

| `t`               | Fields                                             | Meaning                                                                                                                                        |
| ----------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `hello`           | `protocol`, `client`                               | Open the handshake.                                                                                                                            |
| `auth`            | `token`                                            | Authenticate.                                                                                                                                  |
| `prompt`          | `id`, `text`, `auto_approve?`, `images?`, `steer?` | Run one turn. `id` is client-chosen and echoed on `turn_done`. Byte-identical to the field set `sessions/worker.py` accepts.                   |
| `cancel`          | —                                                  | Cancel the active turn (kills a foreground shell command first).                                                                               |
| `interrupt_reply` | `id`, `result`                                     | Answer a pending `interrupt`.                                                                                                                  |
| `command`         | `id`, `name`, `args?`                              | **New.** Run a slash command server-side (`name` without the leading `/`).                                                                     |
| `sessions`        | —                                                  | **New.** Ask for the session list: every session the server holds, with `active` marking this connection's.                                    |
| `attach`          | `session_id`                                       | **New.** Switch this connection to an existing session. Answers `notice` then `sessions`; an unknown id leaves the current session in place.   |
| `create_session`  | `name`, `cwd?`, `resume?`                          | **New.** Spawn a child Nova process, register it, then attach this connection. The child is a chat session; its `/stop`, `/status` and `/clear` are local. `resume` is a saved session id: the child starts with `--continue <id>` in that session's project folder, which is how `/resume` reopens a conversation instead of copying its messages. |
| `close_session`   | `session_id`                                       | **New.** Stop a child this connection spawned. Refused for another connection's session; if it was active, the connection returns to its original session. |
| `screen_result`   | `id`, `result`                                     | **New.** Answer a `screen` frame. `result` is the shape that screen kind documents: a selection id, a form dict or a bool.                     |
| `catalogue`       | —                                                  | **New.** Ask for the command catalogue (`name`, `help`, `aliases`, `wants_text`, `route`, `served`) that drives the client's `/` autocomplete. |
| `approval_mode`   | `enabled`                                          | Toggle auto-approval for the session.                                                                                                          |
| `pty_input`      | `id`, `text` | **New.** Keystrokes for the open terminal: printable characters plus ``, `	`, `` and the arrow escapes. Ignored when no terminal with that id is open. |
| `pty_close`      | `id`         | **New.** Stop the open terminal and release its handle; the server answers with `pty_exit`.                                                          |
| `shutdown`        | —                                                  | Close the session and exit the server loop.                                                                                                    |

### 3.2 Server → client

| `t`              | Fields                                                                                                                                | Meaning                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hello`          | `protocol`, `server`                                                                                                                  | Handshake echo (see §2).                                                                                                                                                                                                                     |
| `ready`          | `protocol`, `session_id`, `cwd`, `model`, `assistant_id`, `ui`, `home?`                                                                | Session is live. `home` is `{"style","animation","version"}`: the saved layout, whether the code rain animates, and Nova's version. The client draws its own banner from it — the terminal UI's fourteen layouts are Textual widget trees, so only the identity every banner layout shares is shared. Additive. |
| `ev`             | `c`, `d`, `prompt_id?`                                                                                                                | One encoded `ui_events` dataclass (see §4). Unchanged from `worker.py`.                                                                                                                                                                      |
| `interrupt`      | `id`, `kind`, `payload`                                                                                                               | Human-in-the-loop request. `kind` is `tool`, `question` or `plan`. Unchanged from `worker.py`.                                                                                                                                               |
| `turn_done`      | `id`, `ok`, `steered?`                                                                                                                | The prompt finished; every accepted prompt gets exactly one.                                                                                                                                                                                 |
| `error`          | `message`, `code?`                                                                                                                    | Fatal for the connection (auth, framing) or a turn-level failure notice.                                                                                                                                                                     |
| `notice`         | `level` (`info`/`warning`/`error`), `message`                                                                                         | **New.** Transient UI notification; never part of the transcript.                                                                                                                                                                            |
| `command_result` | `id`, `ok`, `message`, `blocks`, `action?`, `prompt?`, `screen?`, `attach?`, `create?`, `close?`, `resume?`, `avatar?`                                                  | **New.** Result of a `command` frame; `blocks` is `[{"kind": "text"                                                                                                                                                                          | "code" | "heading", "text": "..."}]`. `action` is `clear` (drop the transcript, then draw this result's `blocks` into it — `/rewind` replays the kept conversation that way, and a clear with no blocks like `/clear` leaves nothing behind), `quit` (close), `cancel` (send a `cancel` frame, as `/stop` does), `theme` (the `ui_theme` frame already carries the palette) or absent. An unknown action is ignored, so adding one stays additive. `prompt` is text the command wants run as a turn (`/init`, `/goal`, `/skill:x`answer this way);`screen`is`{"kind", "title", "payload"}` for a modal the command produced. Both are additive. `attach` is a session id the client should attach to (`/tabs`); the client sends the existing `attach` frame, because only the connection's transport can move its sink. `create` names a tab to spawn and `close` names one to stop (empty means the active tab); the client turns them into `create_session`/`close_session`, and passes `resume` (a saved session id, from `/resume`) through on the create frame. `avatar` is the `/nova` sprite sheet: `{"width","height","fps","foreground","background","frames":[{"state","rows","cells"}]}`, where `cells` are palette indexes and an empty colour string is transparent. It rides one command, so the sprite costs nothing until asked for. |
| `screen`         | `id`, `kind`, `title?`, `payload`                                                                                                     | **New.** Present a modal. `kind` is a shape from the vocabulary in `novacode_cli/ui/port.py` (`list`, `table`, `detail`, `form`, `markdown`, `progress`, `confirm`, `split`), never a widget description, so one client renderer covers every screen. |
| `catalogue`      | `commands`: `[{name, help, aliases, wants_text, route, served}]`                                                                      | **New.** Reply to a `catalogue` frame, in `/help` order. `route` says where the behaviour lives (`passthrough`, `screen`, `client`); `served` says whether the server answers it today.                                                      |
| `sessions`       | `sessions`: `[{id, name, cwd, status, model}]`, `active`                                                                              | **New.** Reply to a `sessions` frame.                                                                                                                                                                                                        |
| `pty`            | `id`, `command`, `text`                                                                                                              | **New.** One chunk of a `!!cmd` shell command's output. `text` is plain lines, already stripped of colour and carriage-return overwrites, and `command` repeats on every frame so a late client can title its pane. |
| `pty_exit`       | `id`, `code`, `command`                                                                                                              | **New.** The command finished with status `code`; the pane stays readable until the user dismisses it.                                                                                                                                 |
| `ui_theme`       | `name`, `dark`, `primary?`, `background?`, `foreground?`, `surface?`, `panel?`, `muted?`, `border?`, `success?`, `warning?`, `error?` | **New.** The palette `/theme` selected: colours are `#rrggbb`, and any omitted field means "keep what you draw with now". The client repaints from the next frame; the transcript is untouched.                                              |
| `notification`   | `notification`                                                                                                                        | Forwarded `session_state` notification (unchanged from `worker.py`).                                                                                                                                                                         |

Every envelope listed as _unchanged_ keeps the exact bytes `sessions/worker.py`
already emits, so `sessions/supervisor.py`, the Cowork server and headless mode
are untouched by this protocol.

### 3.3 Optional session tag

`"s"` may appear on any client → server frame and on `ev`/`interrupt`/
`turn_done`/error frames when one connection multiplexes several sessions. It is
omitted while a connection is bound to a single session, which is the only mode
increment 1 uses.

## 4. `ev` payloads (`ui_events` classes)

Encoded as `{"c": "<ClassName>", "d": {<fields>}}` by
`protocol.encode_event`, decoded by `protocol.decode_event`. Classes are
discovered by reflection over `novacode_cli/ui_events.py`, so a newly added
dataclass is carried without a change here — but only if the client knows it.

| `TextDiscard`        | —                                                                                                                                                   |

## 5. Interrupt kinds and replies

| `kind`     | `payload`                                                           | Reply `result`                                       |
| ---------- | ------------------------------------------------------------------- | ---------------------------------------------------- |
| `tool`     | `HITLRequest` as a dict (`action_requests`, ...)                    | `{"decisions": [...], "any_rejected": bool}`         |
| `question` | question request dict                                               | the HITL response object                             |
| `plan`     | the plan/todos snapshot; `payload["plan"]` is the rendered Markdown | `{"response": <HITLResponse>, "state_update": dict}` |

Every interrupt is resolved in a `finally`, failing closed to
`default_interrupt_response(kind)` when the client dies, disconnects or ignores
it. A missing answer must never wedge the graph and must never mean "approved".

## 6. Failure rules

- **Client gone** mid-turn: the turn is cancelled, pending interrupts resolve to
  the default response, the session is saved as `is_error=True`.
- **Server gone** (socket EOF): the client exits with the server's status and
  leaves the terminal restored.
- **Unported slash command**: `command_result` with `ok=false` and
  `message="<name> is not ported to the ratatui UI yet"`. Never a silent no-op.
  The catalogue in `novacode_cli/server/catalog.py` decides which commands are
  served: a row with `served=false` answers that message, so a half-ported
  command can never look like a command that did nothing.
- **Unanswered screen**: a `screen` frame is always resolved. On timeout
  (`SCREEN_TIMEOUT`, 600 s) or connection close the answer is `null`, which
  every caller documents as its safe default - never an implicit "confirm".
- **One session per connection, many per server.** Every host registers in
  `novacode_cli/server/sessions.py`; `sessions` lists all of them and `attach`
  switches the connection for real: it answers `notice`, then re-sends
  `sessions` with the new `active`. An unknown id keeps the current session and
  says so. Attaching adds the client as a second _viewer_, so the target's
  frames reach both clients; disconnecting removes only that viewer.
- **Capacity is enforced at registration.** A server holding
  `sessions.supervisor.MAX_SESSIONS` sessions refuses the next one with
  `error`/`code:"capacity"` before `ready`, and closes. `ready` still reports
  `capacity` so a client can explain the limit first.
- **Child ownership.** `create_session` spawns a full child Nova through
  `SessionSupervisor.spawn`, bound to the parent's cwd (no new worktree yet).
  `close_session` only stops children that this connection spawned; another
  connection's session is refused with a warning notice. A disconnected
  connection closes its own children. Child tabs are chat sessions: slash
  commands are limited to `/stop`, `/status`, `/clear` and `/quit`, and
  everything else answers the explicit `not ported` result.

## 7. Compatibility with the existing transports

`sessions/worker.py` (stdio child), `sessions/supervisor.py` (parent),
`headless/output.py` and the Cowork app keep their current frames byte-identical.
The server adds frames; it does not modify, rename or reorder any existing one.
Regression set: `tests/test_cowork_server.py`, `tests/test_session_rpc.py`,
`tests/test_session_worker.py`, `tests/test_headless.py`.
