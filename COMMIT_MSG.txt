Wire decision-model tool-result pruning behind a flag, default OFF

Rebased onto current main first: the branch predated f1ac180 ("make the async
agents model-agnostic") and a merge would have deleted _parse_frontmatter_value,
the per-agent model resolution and clear_named_subagents_cache(). The rebase
leaves the branch 3 ahead / 0 behind, and the only change to a pre-existing file
is additive to tool_offload.py.

The feature itself:

- nova_config.py: tool_verdicts_enabled / tool_verdict_endpoint /
  tool_verdict_model / tool_verdict_keep_threshold, all defaulting to OFF, the
  local Ollama System One endpoint and tev1:4b. The threshold is separate from
  the heuristic's keep count because thresholds do not transfer between models,
  or between the two Tev1 sizes.
- core_agent.py: _tool_result_clearing takes an optional verdict cache. Without
  it, the edit returned is byte-identical to today's; with it, a
  VerdictToolUsesEdit whose only difference is the selection. The flag is read
  once at build time and, when off, no client, cache or middleware is
  constructed.
- core_agent.py: the scorer middleware is inserted before
  ContextEditingMiddleware, by index, only when the flag is on. An earlier
  attempt unpacked it into the middleware list literal as `*_([...])`, which is
  not valid syntax there -- ruff's F821 caught it, and it would have broken the
  agent build.
- tool_verdicts.py: build_verdict_middleware() wraps a VerdictScorer in an
  awrap_model_call that queues scoring on the background thread and never
  blocks or fails the turn. parse_answers now raises TypeError for a malformed
  response shape and ValueError only for an unusable value.

Tests (50 pass): flag off returns the original edit object-for-object (same
trigger, keep, excludes, placeholder, clear_tool_inputs); flag on swaps only the
selection and still offloads to /cleared/; a bad threshold falls back; a broken
scorer cannot stop a model call; the insert lands exactly one middleware before
the clearing edit.

Not promoted to default. Measured on six real sessions with both selectors
capped to the same 12-result window, the existing rule cleared 70 results /
72,682 chars at 0.19 regretted per 1k against 49 / 18,364 at 0.44. The model is
good (tev1:4b passes a 12-question positive control 12/12, margin 0.866); the
limitation is that its ~2,000-token context only holds the newest ~12 results of
a session holding 65-308.
